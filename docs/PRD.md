# 拾录 SHILU — 产品需求文档（PRD）

> 版本：v1.0 ｜ 状态：待开发 ｜ 最后更新：2026-11-03
> 本文档为唯一需求基线。任何与本文档冲突的实现或口头约定，以本文档为准；如需变更，先改文档再改代码。

---

## 1. 产品定位

拾录是一个**私有数字资料库**，不是备忘录。它解决的不是"记一下",而是"十年后还能找到、还能看懂、还不外泄"。

| 维度 | 普通备忘录 | 拾录 |
|---|---|---|
| 结构 | 自由文本 | 模板驱动的结构化字段 |
| 附件 | 图片塞进正文 | 统一附件服务，正反面/多图/PDF，可排序可替换 |
| 人 | 无 | 人物档案 + 关系 + 关联资料 + 关联纪念日 |
| 时间 | 无 | 纪念日 + 倒计时 + 重复规则 |
| 敏感 | 明文 | 客户端加密，云端只存密文 |
| 检索 | 全文 | 多维筛选（分类/标签/人物/日期），敏感字段明确排除 |

### 1.1 产品原则（冲突时的裁决顺序）

1. **数据不丢** > 功能多
2. **不泄露** > 好用
3. **结构统一** > 局部特化
4. **真实可用** > 页面齐全
5. 视觉优化放在以上四项之后

## 2. 交付形态：双构建（核心决策）

### 2.1 为什么必须双构建

个人主体小程序提交审核时，"存储用户密码或敏感信息"属于**平台明令禁止**的服务内容。官方社区存在大量因此被驳回的判例，原文口径为：

> 涉嫌在非合理场景下收集、存储用户密码或敏感信息，包括但不限于微信账号、QQ号码、银行账号等，违反《微信小程序平台运营规范》及相关规则，请移除违规后再重新提交代码审核。

该判定与加密强度无关——即使云端只存密文，功能形态本身仍属违规项。

### 2.2 构建矩阵

| 能力 | `public`（上架版） | `private`（自用版） |
|---|---|---|
| 信息库 / 模板 / 附件 / 人物 / 纪念日 / 搜索 / 收藏 / 备份 | ✅ | ✅ |
| 附件客户端加密 | ✅ | ✅ |
| 密码保险箱入口 | ❌ 隐藏 | ✅ |
| `vault` 云函数调用 | ❌ 被云函数侧拒绝 | ✅ |
| 一次性订阅消息 | ✅ | ✅ |

- 开关落点：`miniprogram/config/features.ts`，编译期常量。
- 云端二次校验：`vault` 云函数读取环境变量 `SHILU_BUILD`，为 `public` 时直接返回 `403 FORBIDDEN_BUILD`。**不依赖前端隐藏按钮。**
- 代码不分叉：同一套源码，仅一个常量与一个环境变量不同。

### 2.3 明确不承诺的事

- 不承诺"端到端加密"这一表述用于普通资料。只有保险箱与加密附件属于客户端加密范畴，且其安全性受限于小程序 JS 运行时（见 SECURITY.md §7）。
- 不承诺"纪念日每年自动提醒"。个人主体无长期订阅权限，详见 §8.3。

## 3. 用户与场景

**主用户**：单一自然人，长期（5 年以上）使用，数据量级 10³～10⁴ 条资料、10³ 个附件。

| 场景 | 触发 | 关键路径 |
|---|---|---|
| 存一张身份证 | 办事需要上传证件 | 信息库 → 证件资料 → 新增 → 选模板 → 拍正反面 → 加密上传 |
| 找一个三年前的合同 | 报税/维权 | 搜索"合同" → 按年份筛选 → 打开 → 下载附件 |
| 记住朋友生日 | 怕忘 | 人物档案 → 新增 → 生日 → 自动生成纪念日 → 订阅提醒 |
| 存一个网站密码 | 注册了新站 | 保险箱 → 解锁 → 新增 → 生成随机密码 → 保存 |

首页 / 信息库 / 纪念日 / 我的

> `records` 目录下含 `detail` 与 `edit` 两个子页，不单独建顶层目录。

### 5.3 组件清单（13 个）

`custom-tabbar` / `search-bar` / `record-card` / `category-card` / `field-renderer` / `file-uploader` / `image-preview` / `document-card` / `countdown-card` / `empty-state` / `loading` / `security-dialog` / `tag-chip`

> 原清单中无 `tag-chip`，但标签在 4 个页面复用，抽取避免重复。此为增项，不减少任何原组件。

### 5.4 分层约束

```
page（只做：取参、调 service、绑事件、渲染）
  ↓
component（只做：展示、交互、emit）
  ↓
service（业务编排、缓存、状态机）
  ↓
transport（wx.cloud.callFunction 封装、统一解包、重试、错误映射）
  ↓
cloudfunction（鉴权 → 参数校验 → 归属校验 → 数据访问 → 统一响应）
```

**页面内不得直接出现 `wx.cloud.database()`。** 全部经云函数。

## 6. 非功能需求

| 类别 | 指标 |
|---|---|
| 首屏 | 冷启动到首页可交互 < 1.5s（不含网络） |
| 列表 | 每页 20 条，触底加载 ≤ 300ms 出下一屏 |
| 搜索 | 单次查询 ≤ 800ms（云函数端 100 条上限内） |
| 上传 | 单文件 ≤ 20MB（加密需全量读入内存，超限直接拒绝并提示） |
| 兼容 | 基础库 ≥ 2.13.0；iOS / Android 主流机型；屏幕宽度 320–430pt |
| 可用性 | 所有异步操作有三态（loading / empty / error），error 必须有重试入口 |
| 可访问性 | 正文对比度 ≥ 4.5:1；点击热区 ≥ 88rpx |

## 7. 数据安全要求（摘要，详见 SECURITY.md）

1. 主密码、MK、DEK 永不出现在任何网络请求体中，永不写入 `wx.setStorage`。
2. 云端不存任何明文凭据；附件密文在云存储中以 `.enc` 后缀存放。
3. 授权看 `openid`（云函数从 `getWXContext()` 取），**绝不信任客户端传入的 userId**。
4. 日志脱敏白名单制：只允许打印字段名与长度，禁止打印值。
5. 锁定/退出时置空内存引用并缩短存活窗口（做不到安全擦除，如实记录）。

## 8. 已知限制与未完成项（必须随版本发布）

### 8.1 加密相关的诚实声明

- **未实现 Argon2id**。原因：小程序无 `crypto.subtle`，Argon2id 只能走 WXWebAssembly；Emscripten 默认产出的 wasm 依赖 `wasi_snapshot_preview1` import，小程序不支持，需定制 `STANDALONE_WASM` 编译。当前本机无微信开发者工具、无真机，**无法验证**。故本期落地 PBKDF2-HMAC-SHA512（600,000 迭代），Argon2id 列为 PoC 任务（DEVELOPMENT_PLAN.md P5-PoC）。
- KDF 可插拔：密钥信封记录 `kdf_algo / kdf_params / key_version`，Argon2id 通过后可无缝迁移。
- **JS 无法安全擦除内存**。"锁定时清除临时明文"的实现是置空引用 + 缩短存活窗口，不是内存清零。

### 8.2 平台能力缺口

- 个人主体不可用 `wx.getPhoneNumber` → 人物手机号只能手输。
- `wx.getUserProfile` 已不可用 → 头像昵称已改为 `button open-type="chooseAvatar"` + `input type="nickname"` 微信官方能力（已实现，见「我的」页）。
- 云数据库 `limit`：小程序端 20 / 云函数端 100；无 join；`skip` 深翻页性能差。

### 8.3 提醒能力缺口

- 仅一次性订阅：授权一次 = 一条额度，按 `(openid, template_id)` 分格。额度有效期与下发规则以微信官方文档为准，产品文案不写具体天数。
- 因此"纪念日每年自动提醒"**无法实现**。替代方案：额度累积 + UI 显示剩余次数 + 额度耗尽时如实提示"需再授权"。
- 服务端无法验证客户端上报的授权结果（平台无查询接口），额度只能当"大概还剩几条"；下发返回 43101 时清零。
- 当前构建未配置模板 ID（`cloudfunctions/_shared/reminder-config.js` 留空），因此界面显示"当前构建未配置订阅消息模板，到点不会推送"，不做假承诺。
